مرجع سريع للتمرين Lab quick reference

  1. استيراد: في المحرّر ⋯ ← Import ▸ From file (أو انسخ نص الملف والصقه بـ Ctrl+V).
  2. ربط الحساب: كل عقدة عليها ⚠️ ← اختر Credential.
  3. التجهيز: غيّر your.email@gmail.com إلى بريدك · في 3.1 أنشئ جدولاً بأعمدة Name Email Message.
  4. تشغيل: Execute workflow أسفل اللوحة (قد يظهر باسم Execute).
  5. تأكّد: بريدك، جدولك، والأسلاك الخضراء.

⏰ 3.2 و 3.4: اضغط Publish ليعمل كل يوم تلقائياً — وللتجربة الآن اضغط Execute workflow. الوقت خطأ؟ ⋯ ← Settings ← Timezone.

عندما يحدث خطأ Debugging checklist

  • هل اشتغل المُشغِّل؟ هل ضغطت Execute؟ هل وصل الطلب؟
  • ابدأ من أول عقدة حمراء وافتحها واقرأ الرسالة.
  • افحص INPUT: هل وصلت البيانات التي تتوقعها؟
  • Pin data 📌: ثبّت نتيجة لتجرّب عليها دون إعادة الطلب.
  • Execute step: شغّل عقدة واحدة فقط.
  • Executions: راجع سجل كل تشغيل (ناجح/فاشل).
🔴 مثال حقيقي: Problem in node 'Send digest' — Node does not have any credentials set ← العقدة بلا مفتاح ← افتحها ← Credential ← Connect to Gmail ← شغّل من جديد.

كاشف الدخان Error workflow (Lab 3.5)

  1. استورد error-alert.json، اربط Gmail، ضع بريدك، ثم Execute workflow ← بريد تجريبي.
  2. افتح أي أتمتة أخرى ← ⋯ ← Settings ← Error workflow ← اختر «Lab 3.5 · Error alert» ← احفظ.
  3. يرنّ عند فشل التشغيل التلقائي (بعد Publish)، وليس عند Execute.

عادات ذهبية Best practices

  • سمِّ العقد بوضوح، مثل Save to sheet.
  • أضف Sticky notes تشرح الفكرة.
  • ابنِ خطوة خطوة، وشغّل بعد كل عقدة.
  • جرّب بـ Manual Trigger أو Pin data.
  • الأسرار في Credentials فقط.
  • Publish فقط بعد نجاح التجربة.
  • راقب Executions في الأيام الأولى.
  • اربط Error workflow بكل أتمتة منشورة.
